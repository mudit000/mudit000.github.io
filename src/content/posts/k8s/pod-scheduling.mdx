## Why the scheduler doesn't just pick the first free node

The scheduler runs two phases for every pod: **filtering** (which nodes
even *could* run this pod, based on resource requests, taints, and
affinity rules) and **scoring** (of the nodes that pass, which one is
the *best* fit, based on things like spreading pods evenly or bin-packing
tightly). Only after both phases does it write a binding back to the API
server, which is what actually tells the kubelet on that node to start
pulling the image.
